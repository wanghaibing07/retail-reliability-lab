# 事件：VMnet8 NAT 服务崩溃导致节点无法访问外网

- 日期：2026-09-11
- 环境：VMware Workstation 三节点 Kubernetes 实验集群
- 节点：master `192.168.88.3`、worker1 `192.168.88.4`、worker2 `192.168.88.5`
- 影响：节点无法解析或访问百度，可能影响镜像拉取和外部依赖下载

## 现象

master 的 `ens33`、静态地址和默认路由存在，但 VMware NAT 网关 `192.168.88.2` 不可达，DNS 查询超时。

## 根因证据

宿主机 `VMware NAT Service` 启动后反复退出。Windows Application Error 记录：

- `C:\Windows\SysWOW64\vmnat.exe`
- VMware Workstation `17.5.0`
- 先后出现 `0xc0000005` 和 `0xc0000374`
- 服务最终进入停止状态

升级 x86 Visual C++ v14 运行库后，`vmnat.exe` 仍然崩溃，因此问题不是单纯缺少运行库。

## 修复动作

1. 为三台 VM 创建并验证快照 `pre-nat-repair-20260911`。
2. 保持 VMnet8 网段和节点地址不变。
3. 在宿主机创建 Windows NetNat：`K8sLabWinNat`，内部网段为 `192.168.88.0/24`。
4. 三台 Guest 的 NetworkManager 持久配置改为：
   - 网关：`192.168.88.1`
   - DNS：`223.5.5.5`、`114.114.114.114`
5. 将崩溃的 VMware NAT 服务设为手动并停止，避免持续崩溃循环。

## 验证

- 三节点连续 ping `baidu.com`：0% 丢包。
- 三节点访问 `https://www.baidu.com`：HTTP 200。
- Kubernetes：master、worker1、worker2 均为 `Ready`。
- 节点 IP、Pod CIDR 和 Service CIDR 未改变。

## 回滚条件

只有在 VMware Workstation 升级并确认 `vmnat.exe` 稳定后，才按“停 VM → 移除 Windows NetNat → 恢复 VMware NAT → 恢复 Guest 网关/DNS → 重新验证”的顺序回滚。
